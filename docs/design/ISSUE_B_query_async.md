# 질문 처리 비동기화

질문 처리·읽기 보호·대화 정합성·종료 보호를 같은 기능으로 구현했다. 자동 회귀는
사외 fake/임시 DB/Qt 이벤트 루프/JS 실행 환경에서 검증하며, 실제 Windows·Office·사내 API와
장시간 현장 검증은 남아 있다. 상태는 [ROADMAP](../ROADMAP.md), 화면 동작은
[UI_SPEC](../../UI_SPEC.md)를 따른다.

## 실행과 수명

`Bridge.sendQuery`는 입력을 검사하고 요청마다 `QueryWorker(QThread)`를 만든다.
GUI에서 검색·임베딩·LLM을 실행하거나 양수 `wait()`로 기다리지 않는다. 요청 전용
`AgentRegistry`와 DB/HTTP/crypto 객체는 워커 안에서 생성·사용·해제한다.

`QueryController`가 한 요청의 실행권을 유지한다. 결과나 `finished`만으로 실행권을 풀지 않고,
`wait(0)`으로 실제 종료를 확인한 뒤 참조를 해제한다. 아직 종료되지 않았으면 QTimer로 재확인한다.
추가 질문은 대기열에 넣지 않고 거절한다. 질문 워커에는 `terminate()`를 사용하지 않는다.

상태는 `IDLE → RUNNING → 실제 종료 확인 → IDLE`다. 취소·시간초과·화면 탐색은
`RETIRED_PENDING_EXIT`로 바꾸고 늦은 결과를 버린다. `CLOSING`은 새 요청을 받지 않는다.

## 질문 전용 인덱스 읽기

`QueryReader`는 기존 `index`의 chunks/emails 테이블만 연다. 인덱서·추출기·Office와
DB 생성/이전/수정/정리 경로를 호출하지 않는다. 테이블 한쪽이 없으면 해당 검색을 생략하고,
필수 스키마가 맞지 않으면 인덱싱 준비 안내를 반환한다. 암호화 키도 기존 `km.key`만 읽는다.
키 없음·복호화 실패를 키 생성이나 fake 암호화로 우회하지 않는다.

요청은 GUI에서 복사한 설정과 확정된 데이터 경로를 사용한다. 검색은 필요한 컬럼을 projection하고
기존 범위·owner·삭제·날짜·점수·출처 규칙을 유지한다. 제외된 문서·메일은 물리 삭제 실패 시에도
요청 설정으로 복호화 전에 걸러낸다. 각 질문은 새 DB 핸들을 열어 완료된 쓰기를 다음 질문에서 읽는다.
질문 중 두 테이블의 전역 원자성이나 항상 최신 결과를 보장하지 않는다.

운영 임베딩은 `api`, 테스트는 명시적 `fake`를 쓴다. `local`은 안내하고 시작하지 않는다.
DB·대화 스키마와 인덱스 버전을 바꾸지 않으며 재인덱싱을 요구하지 않는다.

## UI와 대화 저장

요청과 응답은 `request_id/thread_id/mode/view_generation`으로 연결한다. 사용자 메시지의
저장 성공 ACK 뒤 질문을 보내며, 일치하는 화면에만 답변을 표시·저장한다. 저장 실패 시 입력과
현재 대화를 보존하고, 실패한 대화의 탐색 전 저장을 다시 시도한다. 삭제 ACK도 확인한다.

모드 전환·새 대화·복원·활성 대화 삭제는 화면 세대를 무효화하고 이전 요청을 취소한다.
최근 목록은 `recentListSeq/historyMutationEpoch`, 복원은 `restoreSeq`까지 확인해 역순 응답을
버린다. 복원할 때 목록의 낡은 메시지를 재사용하지 않고 `getThread`로 최신 저장본을 읽는다.

입력 편집·창 조작·화면 탐색은 계속 가능하다. 실제 워커 종료 전에는 새 질문 전송과
설정 저장·폴더 추가/삭제·단일/일괄 제외/해제를 거절한다. 쓰기 요청은 보관하지 않으며
사용자에게 완료 뒤 다시 시도하도록 알린다. 인덱싱 중 제외/해제 금지도 유지한다.

## 취소·오류·시간초과

번들 `ui.query_timeout_seconds`가 기본 대기 예산 정본이다. 유효한 양수만 사용하고,
백엔드 타이머가 요청별 시간을 관리한다. 프런트 안전 타이머는 상태를 재조회/취소할 뿐
실행권을 해제하지 않는다. 취소는 thread-safe Event와 `EmbeddingCancellation`로 후속 단계를 막는다.
LLM/네이티브 DB/외부 SDK의 즉시 중단은 보장하지 않는다. 정리가 끝나기 전에는 새 워커를 만들지 않는다.

일반 오류는 고정 안내와 오류 종류로 제한한다. 초기화 내부에서 잡은 예외도 traceback,
예외 문자열, 청크·질의·토큰을 진단 로그나 debug 블록에 넣지 않는다. 정상 답변·출처·사용자
대화의 기존 저장은 유지한다. 결과가 없거나 직렬화/전달에 실패하면 GUI가 오류 terminal을 한 번 보완한다.

## 실제 앱 종료

트레이 숨김은 요청을 유지한다. 실제 종료는 먼저 query admission을 닫고 취소를 시도한 뒤,
기존 PPT 준비·스케줄러·Office/수집기 정리를 수행한다. 각 단계와 진단 로그 실패를 격리해
수집기/Office 정리를 건너뛰지 않는다.

수집기 종료가 unsafe이면 query 확인·대기·추가 로그 없이 기존 최종 hard-exit 판정으로 간다.
수집기가 안전할 때만 query에 최대 8초의 종료 유예를 준다. 실제 join이 확인되지 않거나
query 종료 절차가 실패하면 unsafe로 합산한다. 기존 dirty-shutdown 표식과 정상/강제 종료 규칙을 따른다.

## 검증과 남은 현장 확인

자동 회귀는 실제 Qt 루프의 GUI heartbeat, single-flight와 join 지연, 취소·늦은 결과·중복 terminal,
정책 쓰기 gate, 대화 ACK와 역순 목록/복원, 기존 DB/키 보존, projection·제외·검색 의미,
동시 인덱스 쓰기와 다음 요청 최신성, Office 종료 합산을 다룬다.

사내 Windows에서는 첫/후속 질문·인덱싱 병행 중 창 이동·최소화·트레이 복원·대화 탐색과
정상/오류/timeout의 저장 대상을 확인한다. 질문 중 실제 종료, DPAPI·Office 보호,
30회 이상 질문의 메모리·스레드·핸들 누적과 기존 버전 대비 답변·출처도 확인한다.
실제 QWebEngine 렌더링이 실행 불가인 환경에서는 Qt QWebChannel/JS 통신 검증과 구분해 보고한다.
